# 小程序运行架构

## 数据流

```text
知识图谱数据管道
      ↓ 生成与校验
characters / relations / factions / locations / items / quotes / timeline
      ↓ 静态资源发布
HTTPS 数据与图片服务
      ↓ Taro.request
内存缓存 + 微信 Storage 缓存
      ↓
页面、搜索、图谱、分享卡片与 UGC 入口
```

小程序不在客户端执行小说抽取或知识图谱构建。客户端只消费已生成的轻量 JSON，并在需要详情时按文件加载。

## 目录职责

- `src/app.config.ts`：页面注册和底部导航。
- `src/data/dataTypes.ts`：客户端数据契约。
- `src/data/useData.ts`：请求、缓存、预加载和资源回退。
- `src/components/Graph/`：关系图谱与人物信息面板。
- `src/pages/`：首页、实体详情、世界、搜索、对比、时间线、地图和 UGC 页面。
- `src/utils/`：分享 Hook、数据埋点、Canvas 卡片生成和视口工具。

## 缓存策略

数据先进入内存缓存，再使用微信 Storage 持久缓存。缓存命中时优先返回本地数据；网络失败时允许回退到过期缓存。修改缓存时必须同时考虑：

1. 首屏速度；
2. 数据发布后的可见延迟；
3. Storage 配额；
4. 缓存版本升级和失效策略。

## 图片策略

图片按以下顺序回退：

1. 数据 JSON 中提供的已审核资源 URL；
2. 资源服务器上的项目图片；
3. 客户端维护的少量回退映射；
4. 纯色文字占位图。

2300 张生成法宝图不进入 Git 和小程序包体，通过资源服务器按需加载。只有二维码、分享模板、导航图标和少量必要回退资源随客户端发布。

## UGC 边界

客户端只负责收集修订内容并提交到审核 API。提交内容必须经过服务端鉴权、限流、格式校验、文件类型检查和人工/自动审核，不能直接写入正式数据。

设备标识、图片上传和分析事件在上线前必须完成隐私评审。任何稳定标识都应有明确用途、最短保存期限和退出机制。

## 发布边界

- `npm run build:weapp` 只生成小程序制品，不发布到微信。
- 数据 JSON 与图片服务独立发布，不随 Git push 自动更新。
- GitHub、静态资源服务器和微信平台三处状态必须分别验证。
